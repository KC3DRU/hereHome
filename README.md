# Here - Location Sharing App

A simple Android app with three home screen widgets for sharing your GPS location via SMS.

## Features

### 📍 "I Have Arrived" Widget
When tapped, sends an SMS to your designated contact with:
```
I am here. https://maps.google.com/?q=<lat>,<lng>
```

### 🏠 "Heading Home" Widget
When tapped, sends an SMS to your designated contact with:
```
I am heading home from here. https://maps.google.com/?q=<lat>,<lng>
```

### 🚗 "Moving On" Widget
When tapped, sends an SMS to your designated contact with:
```
Moving on to the next stop, leaving from here https://maps.google.com/?q=<lat>,<lng>
```

## Setup (First Time)

Opening the app from the launcher shows the **setup dialog** — that is the only place
configuration happens:

1. **Add recipients** — enter a number and tap **Add** (see **Phone numbers** below).
   Add as many as you like; every recipient gets the same message.
2. **Remove a recipient** with the **✕ Remove** button beside their number.
3. **Grant permissions** with the red **Request...** buttons — SMS (to send) and GPS (to locate).
   If you grant only *Approximate* location the app still works; the button stays so you can
   upgrade to exact.
4. Dismiss the dialog. There is no separate save button — numbers are stored the moment you add them.

### Phone numbers

US numbers may be entered in any of these forms — all are accepted:

```
212 555 0100
(212) 555-0100
2125550100
+12125550100
```

The app stores them in E.164 (`+12125550100`), so `(212) 555-0100` and `2125550100` are recognised
as the same contact and cannot both be added. The "Added:" confirmation shows the stored E.164 form,
and removing a recipient matches on it too.

**International numbers must include the `+` and the country code** — for example `+44 20 7946 0958`
is stored as `+442079460958`. A bare 10-digit number is assumed to be US. **Seven-digit numbers are
rejected** (no area code), as is anything that cannot be a phone number; the app says
"Not a usable number — try 212 555 0100 or +1 212 555 0100" and leaves the list untouched.
Numbers saved by older versions are normalised automatically the first time they are read.

## Adding Widgets to Home Screen

1. Long-press on an empty area of your home screen
2. Tap **Widgets**, then find **Here**
3. The three entries are labelled **I have arrived**, **Heading Home**, and **Moving On**.
   Builds before v1.2 listed all three as "Here"; widgets already on your home screen are
   unaffected by the fix and keep working — only the names in the picker changed.
4. Drag any of them onto your home screen

As of v1.3 the widgets are offered as **1x1** (`minWidth`/`minHeight` 40dp, `targetCellWidth`/
`targetCellHeight` 1) and can be stretched larger — drop one on a tight spot in the grid and pull it
out to whatever size you like.

## The Two Dialogs

There are exactly two, and which one you see depends on how the app was opened:

| Opened from | You get |
|---|---|
| App icon | **⚙️ Here — setup** — permissions, add recipient, remove recipient |
| A widget | **Send dialog** — which message, to whom, and the exact text |

The send dialog names the message (`📍 I have arrived` / `🏠 Heading Home` / `🚗 Moving On`), lists
every recipient number, shows the exact body being sent (long-press to copy it), and reports live
status: `Acquiring GPS fix` → `📤 Queued with radio` → `✅ Sent`, or the reason it stopped. If a
widget tap cannot proceed — no recipients, or no SMS permission — it says which and offers a button
straight into setup rather than sitting there.

## How It Works

1. Tap a widget on your home screen
2. The app opens and captures your current GPS coordinates
3. A Google Maps URL is constructed from those coordinates
4. The pre-configured message is sent via SMS to your contact
5. You see the result (success/failure) in the app

## Requirements

- Android 8.0 (API 26) or higher
- A phone with SMS/cellular capability (not Wi-Fi only)
- Location services enabled on the device
- GrapheneOS compatible (uses standard Android permissions APIs)

## Technical Details

- **Language**: Kotlin
- **Architecture**: Activity-based with coroutines for async operations
- **Location**: Android framework `LocationManager` (GPS/network) — **no Google Play Services**
- **SMS**: Android `SmsManager` (direct SMS send through carrier)
- **Storage**: SharedPreferences for contact number
- **Widgets**: Three separate AppWidgetProvider components
- **100% FOSS**: Zero Google Play Services dependency — works on GrapheneOS out of the box

## Note on the application ID

The app id is `io.github.kc3dru.here`. If you previously installed an earlier build that used
the placeholder `com.example.here`, Android considers it a completely different app: uninstall
the old one first, otherwise both will be installed side by side and any widgets you had placed
belong to the old one.

## Building

### Automatic (recommended)

```bash
# From the directory you cloned this repo into:
cd hereHome
bash build.sh
```

This script installs the Android SDK command-line tools, Gradle, and builds the APK.

### Manual

```bash
# Install prerequisites
sudo apt install openjdk-17-jdk-headless unzip wget

# Then either:
./gradlew assembleDebug    # Debug build
./gradlew assembleRelease  # Release build (with ProGuard)
```

The APK will be in `app/build/outputs/apk/`

## Security Notes

- The contact number is stored locally in app preferences, which are excluded from
  cloud backup and device-to-device transfer
- No data is sent to any server — SMS goes directly through your carrier
- No internet connection is required (location is from GPS, URL is just text), and the
  app declares no `INTERNET` permission
- Recipient numbers and message contents are never written to logcat
- Works on GrapheneOS without any Google Play Services or microG

## Getting a Location Fix Faster

The app uses a cached fix from any enabled provider if it is younger than 60 seconds, so a
second tap right after the first is near-instant. Otherwise it queries every enabled provider
simultaneously and takes the first fix that arrives, up to 30 seconds. Enabling the OS
network/Wi‑Fi location provider (on GrapheneOS: **Settings → Location → Location Services**)
makes indoor fixes considerably quicker than GPS alone.

If you grant only *Approximate* location, the app still works and sends a coarse Maps link;
the settings screen shows `⚠️ GPS permission: approximate only` with a button to upgrade to exact.
